# 流派可视化文法 v1 · 从 Jazz 站沉淀（2026-07-03）

> 目标：让"音乐类型可视化"成为一个系列——下一个流派尽量只填数据、不重写代码。
> 依据：snare_dial_v5.html 逐行拆解（本文档末尾附耦合度表），不是拍脑袋。

## 一 · 内容文法（一个流派章 = 一份数据）

一个"节点"（notch）由这些字段构成，Jazz 站已验证：

```
{ id, year, name（流派名）, theta（拨盘角度）, href（段落页）}
+ DJ 块：meta 行（年份·流派·代表曲）/ 标题 / DJ 介绍词 / Spotify track ID
+ 段落页：section_XX.html（每流派一页深读）
```

一个完整流派章 = **8 个左右节点 × 上述字段 + 1 张封面 + 分隔卡**。这就是"填数据"的全部内容工作。

## 二 · 交互文法（可整体复用）

- **鼓件 = 容器，拨杆 = 时间轴**：拖动/点击/键盘三种输入，松手磁头感吸附（cubic-bezier(0.2,0.85,0.25,1) · 0.55s），走最短路径不绕圈
- **一次只响一个**：切节点 = 高亮 + 转杆 + 自动播当前曲、暂停其它（Spotify iframe API，逻辑与流派无关）
- **封面态**：落地不展开，拨杆平放在第一个节点旁
- **铁律（STATUS_LOG 已沉淀）**：装饰元素不能长得像可交互的

## 三 · 编辑文法（系列的差异化所在）

**鼓手视角贯穿**：每个流派章回答同一个问题——"鼓在这个流派里发生了什么"。这是本系列区别于一切泛音乐史内容的锚，比引擎更重要。DJ 介绍词短句、口语、留白，与 ChenListen 慢生活立场同调。

## 四 · 工程现状（v5 耦合度 · 子代理拆解结论）

| 可直接复用 | 必须动手的 |
|---|---|
| Spotify 播放逻辑 / easing / 布局框架 / CSS 色板体系 | 9 个节点的 SVG 坐标硬编码（手算的极坐标→直角） |
| notches 数组（换数据即可） | 鼓面标题"JAZZ/1899-1969"写死在 SVG 里 |
| DJ 块结构（data-event 对齐即可） | 节点数量增减要改 HTML 结构 |

引擎化（配置驱动 + 坐标自动生成）≈ 290 行 JS 可参数化 80%，做完后新流派 = 1-2 小时填数据。

## 五 · 路线建议（我的推荐 + 理由）

**第二个流派：复制 v5 改数据，不做引擎。** 理由 = 三次法则：n=2 就抽象是过早抽象，第二个流派做的过程会暴露 jazz 专属假设（比如"拨盘=年代"对无明确年代锚的流派是否成立），**引擎等第三个流派动工时再抽**，那时抽象才有两个真实样本支撑。这与《不设限的产出》结论同构：原则/引擎都是回望的产物。
复制时顺手做一件事：把散落的 SVG 坐标改为从 notches 数组生成（拆解报告里 40% 工作量那项），为日后引擎留缝。
